# d2q NFC bring-up — investigation notes (2026-11-04)
**Device: SM-N9750 (d2q) · Debian 12 · kernel 4.14.190-ShinyKernel**

## ✅ RESOLVED SAME DAY — CARD EMULATION (Type-4A / ISO-DEP) WORKS

**d2q presents as a valid NFC-A Type-4A tag to an external reader phone on Debian.**
Evidence: `/home/usb/mnt-sda/camera-recon/ce-success-2026-11-04.log` — 34×
`RF_INTF_ACTIVATED iface=02 proto=04 mode/tech=80` (ISO-DEP over listen NFC-A passive)
with RF_DEACTIVATED cycles, user-confirmed tag detection on the reader phone.

**Root cause of the previous failure (pn547_ce.c):** it sent `21 02 …` believing it was
RF_SET_LISTEN_MODE_ROUTING. Per NCI 1.0 (`nci_defs.h` of NXP/AOSP libnfc-nci):
- `21 01` = RF_SET_LISTEN_MODE_ROUTING (SET) — never sent
- `21 02` = RF_GET_ROUTING (a read-only query) — what was actually sent
So the chip listened but had **no route from NFC-A listen to the DH**, hence never
activated. The tech byte was also wrong: `0x80` (LISTEN-A *discovery type*) instead of
`0x00` (`NCI_RF_TECHNOLOGY_A`). Correct command:

```
21 01 07 00 01 00 03 00 01 00
   │  │  │  └─num_tlv=1 └─TLV: [tag 0x00 TECH][len 3][NFCEE 0x00 DH][pwr 0x01 on][tech 0x00 NFC-A]
   │  │  └─more=0 (single block)
   └──┴─RF GID/SET_ROUTING, payload len 7
```

Verified on-chip: SET_RSP `41 01 01 00` OK; GET_ROUTING NTF `61 02 07 00 01 00 03 00 01 00`
echoes the entry back from the routing table.

**Second fix — full NXP proprietary init.** The raw-NCI tool previously skipped every NXP
proprietary config block. Reconstructed the complete stock sequence (NXP
NFC_NCIHAL_libnfc-nci pn5xx halimpl + stock Samsung confs) in `pn547_ce2.c`:

1. `CORE_RESET 20 00 01 00` (reset config, HAL-style; no CORE_RESET_NTF follows on this FW)
2. `CORE_INIT 20 01 00` → FW decode: **rom=0x11 (PN553), fw 41.21** — equals the stock
   `libpn553_fw.so` image version (0x4121) ⇒ no firmware download needed (HAL's
   `phNxpNciHal_CheckFwRegFlashRequired` logic would also skip)
3. `2F 02 00` (ACT_PROP), `2F 00 01 01` (standby), `20 02 05 01 A0 07 01 03` (VEN pull-down)
4. Clock: GET A0 02/03/04 → if A0 03 ≠ 0x11 or A0 04 ≠ 0x06 send A0 03=0 +
   `SET_CONFIG_CMD_PLL_19_2MHZ` + `SET_CONFIG_CMD_DPLL_19_2MHZ` (phNfcCommon.h:88/93)
5. PROFILE_EXTN `A0 44=0` (Nfc Forum mode), RF_CONF_BLK_1..4 (CLIF analog + **DLMA load-
   modulation table** — BLK 3 needed a machine-generated array; hand transcription had 8
   extra bytes → STATUS_SYNTAX_ERROR 0x05), CORE_CONF_EXTN, CORE_CONF (LA_BIT_FRAME_SDD
   0x08, LA_PLATFORM_CONFIG 0x03, **LA_SEL_INFO 0x20 = ISO-DEP**, LA_NFCID1 random),
   MFCKEY, SWP timeout/full-pwr, screen state `2F 15 01 00`
6. `CORE_CONN_CREATE` static RF conn, `RF_DISCOVER_MAP {ISO-DEP listen → ISO-DEP iface}`,
   **SET ROUTING (the fix)**, GET ROUTING readback, `RF_DISCOVER {listen NFC-A freq 1}`
7. Host serves Type-4A: CC file E103 + NDEF file E104 (starts empty NLEN=0 so write-mode
   apps see an empty formatted tag), APDUs on NCI data conn

All commands STATUS_OK on device; readbacks confirm `LA 30=08 31=03 32=20`,
`A0 44=0x00`, tag-detector `A0 40=0x05`, clock A0 02/03/04 = 01/00/01 (A0 03 stays 0x00
— the pn553 HAL also always re-applies PLL since its readback check can never pass).

## Hardware (unchanged context)

- NFC controller: **NXP PN553** (i2c-12 @ 0x2b, DT node named `pn547`, vendor driver `pn547` → char dev `/dev/pn547` major 10 minor 83). A second unbound `nq-nci` node exists at i2c-9 @0x28 (unused alt interface).
- **The antenna is physically on the wireless-charging plate.** With the plate removed the chip is alive but nothing RF works. Confirmed working after reassembly.
- pn547 kernel driver interface: `PN547_SET_PWR` ioctl (`_IOW(0xE9,0x01,long)` = **0x4008E901** on arm64 — 8-byte `long`), then NCI read/write on the fd. Read blocks via wait_event. One exclusive open at a time (EBUSY if held).
- Kernel driver traps: `CONFIG_NFC_PN547_CLOCK_REQUEST` is NOT set (no msm_xo clock vote; clk_req gpio113 IRQ is wake-only). The clock path is hardware-autonomous (no clocks property in DT; same driver+kernel works on stock Android). i2c read: **max ~260 bytes like the vendor HAL** — 512-byte reads wedge the GENI I2C controller (returns 512 bytes of 0xff padding, then next read hangs forever inside i2c_master_recv).

## What works (verified on-device)

- **Chip alive + NCI sane:** CORE_RESET_RSP `40 00 03 00 10 01`, CORE_INIT_RSP `40 01 19 00 03 0e 02 01 ... 80 82 83 84` (RF interfaces incl. ISO-DEP 0x02).
- **Reader (poll) mode WORKS:** RF_DISCOVER with poll configs (tech 0x00/0x01/0x02, freq 1) → the d2q detected a real ID card: `RF_INTF_ACTIVATED 61 05 ... proto T2T, UID ba:95:6d:21`. So the antenna radiates and receives; the RF front-end is configured fine for reader mode with **no special config**.
- **Listen mode field detection works:** in listen mode the pn547's IRQ fires when the other phone polls nearby (the field IS detected).

## What doesn't work (the wall)

- **Card emulation (d2q as a tag):** the pn547 detects the reader's field (IRQ fires) but does **not** present a valid tag — the other phone sees nothing. RF_DISCOVER with listen config returns status 00, so the listen is "accepted" but the anti-collision/SELECT response is wrong/absent.

## NCI sequence I built (pn547_ce.c)

The right pieces, assembled from the NXP halimpl source + kernel NCI lib:

```
CORE_RESET       20 00 01 01            (keep config)
CORE_INIT        20 01 00
SET_CONFIG       20 02 04 01 32 01 20   (LA_SEL_INFO 0x32 = 0x20 ISO_DEP bit → Type-4A tag SAK)
SET_CONFIG       20 02 07 01 33 04 08 44 32 51   (LA_NFCID1 0x33 = 4-byte UID 08 44 32 51)
RF_DISCOVER_MAP  21 00 04 01 04 02 02   (ISO_DEP proto 0x04, mode LISTEN 0x02, iface ISO_DEP 0x02)
RF_SET_LISTEN_MODE_ROUTING  21 02 07 00 01 [00 03 00 01 80]
                  (1 tech-route TLV: type 0x00, len 3, NFCEE=0x00 DH/host, pwr 0x01, tech 0x80 listen-NFC-A)
RF_DISCOVER      21 03 03 01 80 01      (1 config: listen NFC-A 0x80, frequency 0x01)
```

Then loop reading for RF_INTF_ACTIVATED (61 05) and ISO-DEP APDUs (00 A4 / 00 B0), serving a Type-4A
CC file (E103) + NDEF file (E104, NLEN-prefixed text record "d2q NFC"). The ISO-DEP/NDEF responder
logic is written and correct on paper.

## Traps / gotchas found

- **RF_DISCOVER config entry = [rf_tech_and_mode][frequency]** — there is NO protocol byte there
  (protocol is set later via RF_DISCOVER_SELECT). An early version mis-set a "protocol" byte that was
  actually read as frequency.
- **ISO-DEP protocol = 0x04** (NOT 0x03; 0x03 is T3T). SEL_INFO ISO-DEP mask = 0x20.
- `pkill -f pn547` inside an ssh command kills the ssh shell itself (the cmdline contains "pn547").
  Use `killall -9 pn547_ce` (exact name) instead.
- The pn547 read blocks (wait_event) — add `timeout` to test runs.
- A hung test process holds /dev/pn547 exclusively → subsequent opens fail EBUSY; `killall` first.
- Discovered earlier run left `/dev/pn547` held → "Device or resource busy".

## The missing piece (hypothesis)

Reader mode works with zero config, so the RF front-end is fine. CE presents an invalid tag. Most likely
the pn553 needs its **firmware patch** (`libpn553_fw.so`, in stock vendor `/firmware/nfc/`) downloaded at
init — the vendor `libnfc-nci` does this via the `firm_gpio` download mode + the NXP download protocol
(`phNxpNciHal_Dnld`). The ROM firmware handles reader mode; CE may need the patched firmware. Secondarily,
the exact listen-mode antenna config (NXP_RF_CONF_BLK_* / NXP_CORE_CONF_EXTN) may be required for the
anti-collision to present correctly.
