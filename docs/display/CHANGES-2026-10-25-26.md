    /* userspace only; kernel-context commits (splash handoff, fbcon restore) untouched */
    for_each_new_plane_in_state(state, plane, new_ps, i) {
        old_ps = plane->state;
        if (!new_ps->crtc || new_ps->fb != priv->fbdev->fb) continue;
        if (!old_ps || !old_ps->fb || old_ps->fb == priv->fbdev->fb) continue;

    }
    return 0;
}

## J. 2026-10-26 night — the residual motion-freeze root cause; image 300 (async kicks)

* User report on 299: content only updates when the cursor STOPS (selection
  box jumps to the finger on release; MC menu freezes during mouse motion);
  MC fps steady 20-30 with frametime FLAT, GPU ≤30 %.
* Measured on 299: DIRTYFB kicks commit inline in 8-17 ms (they wait for the
  panel TE inside msm_atomic_commit). Xorg's block handler pays that wait on
  EVERY dispatch cycle; flush cadence tracks input rate (strace: 124
  flushes/2 s under synthetic motion, all ret=0). Under mouse-rate input
  the per-cycle TE wait saturates the server loop: client drawing and
  present copies queue behind motion events → screen frozen while moving,
  catches up on stop. At idle it is invisible (MC 26 fps = one 8 ms kick
  per frame). Frametime flat = MC's own loop healthy; the stall is X's
  main thread between MC and the panel. Cursor is a SOFTWARE (glamor)
  sprite (zero DRM_IOCTL_MODE_CURSOR during motion) — it rides the same
  flushes, hence "cursor fine, content frozen" is perception, not a hw
  cursor.
* Fix = image 300 `300-halium-boot-asyncdirty.img`
  (sha256 `020f08e23cdc4f96b28ab51adf981a2198a341fa484a8b6273b52eaf5e4c224c`):
  msm_fbdev_dirty no longer commits inline. It arms a collapsed work item on
  a dedicated "d2qkick" workqueue (max_active=1); the worker re-asserts the
  current plane state (plane-only atomic commit) at most one per burst —
  Xorg's dirtyfb returns in µs, dispatch runs at input rate, panel still
  refreshes at TE rate. DPMS-off → skip; fb-not-on-plane → legacy fbcon
  restore fallback. Kernel Image-dtb sha 49eb3cea…; packed with the full
  ramdisk; REFERENCE=298 header check passed (id-field-only diff).
